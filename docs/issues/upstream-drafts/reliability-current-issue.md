# Improve AirFlash reliability, pairing and diagnostics

Delayed receiver work can outlive user intent, a missing DNS completion can suppress another lookup, and terminal engine events can leave pairing input open. This tracker covers the remaining safeguards, recovery and diagnostics work against reviewed Main `439de6260e01efbfca528a12cf4d4c1010b3583e`.

Issues #14 and #24 remain the canonical session-intent and authentication reports; authentication PR #25 remains open. Main already includes SDK preflight, Settings scrolling, MSI payload refresh, configuration recovery, partial passive transport retention and native IPC/EQ preparation results. Preserve those integrations and the contributors' software stereo, application capture/standby, schema-4 settings, receiver profiles/rates, password support and language catalogs.

## Current behavior and bounded triggers

Retained isolated regressions reproduce these specific failure paths at their recorded pre-fix sources:

- Hold identity persistence, start a newer Pair, then finish the old save and perform an unrelated settings flush. Delayed work can replace the newer attempt's effective options, restart it at defaults or override newer intent.
- Inject a missing DNS completion and advance the fake monotonic clock. A logical request needs a finite deadline and bounded retry; late results must not publish obsolete data or release a newer request's ownership.
- Load a schema-4 software group with a null ID. Validation must return a controlled result through the existing original-byte preservation path instead of throwing from string operations.
- Deliver a terminal engine event while PIN/password input is open. Input must be cancelled and joined without abandoning the sole event reader or submitting a stale value.
- Inject credential/password open/read failures, mixed verification arguments or linked package-cleanup paths. Failures must remain actionable and must not select a different authentication method, run the wrong fixture or perform unsafe cleanup.

Synthetic capture queues and mute journals additionally exercise missing-frame accounting and interruption/recovery states. These are executed fake-service controls and source-derived failure boundaries. They do not reproduce a particular HomePod/network incident or demonstrate physical power-loss behavior.
