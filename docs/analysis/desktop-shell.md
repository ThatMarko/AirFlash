## Shutdown correction — 2026-10-18

The comprehensive audit reproduced the pinned shell's admission gap with a held real Settings Apply and synthetic engine/audio services. Earlier VM-disposal fixtures bypassed the shell's preceding waits. [B correction `d7782a3`](https://github.com/ThatMarko/AirFlash/commit/d7782a3d069f996b6d1c7c2fe65b224b6f13aa8e) makes actual Quit call `ShellShutdown.RunAsync`: `BeginShutdown` closes admission and invalidates intent synchronously before the first await. Accepted Apply/dirty saves still commit, while post-save runtime updates cannot restart playback during closing. Discovery teardown remains at deferred VM-disposal entry, after the shell has awaited Settings Apply; a dirty save can still be outstanding when discovery is disposed. The helper attempts Apply completion, window cleanup, engine-probe disposal and VM disposal despite earlier stage errors, preserving a single original error or all errors in order.

Owned Stop remains usable during held cleanup. Current session publications continue updating the shell, and inactive Play is disabled while closing; successful Stop must therefore publish Idle and disable the bound Stop/row commands. The separate `--ui-smoke --ui-shutdown-smoke` route and full lifecycle harness exercise the same helper called by actual Quit. [Current B acceptance](../issues/GROUP-B-ACCEPTANCE.md) records the failed unchanged-order control, both-SDK results and regional qualifications. This supersedes the first-Quit-await limitation below; it does not promise a hard cleanup deadline, physical crash durability or terminal-event handling inside an already open PIN prompt.

## From executable to a usable shell

[Program.Main](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Program.cs#L17) is STA. DNS helper and synthetic helper-check dispatch return before WPF, platform probes, logs or application data initialization. Actual other diagnostic modes select an isolated data/log directory before probing Windows or loading WPF resources. The broader `IsDiagnostic` predicate controls startup-error presentation; a random argument ending in `-check` does not independently activate data isolation or a diagnostic service.

Ordinary startup logs platform/resource stages, checks Windows 10 version 1809/build 17763 or newer with both process and OS x64, then runs the WPF Application. [WindowsCapabilities](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/WindowsCapabilities.cs) separately probes the DNS-SD exports. Missing DNS-SD pauses discovery and explains manual-entry availability; it is not the same as failing the host requirement. Window-color capabilities require Windows 11/build 22000; optional DWM failures are logged without changing the host requirement.

[App.OnStartup](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/App.xaml.cs#L100) acquires the ordinary single-instance boundary before config/store creation. One SettingsStore is loaded once for language/theme and again by AppViewModel. The store carries recovery obligations across those loads. It then constructs production audio, discovery, extraction factory, initialization state, panel and tray, and installs event/activation handlers.

The view-model startup task begins mute-recovery initialization, then default-endpoint lookup, autostart reconciliation and old endpoint-name migration. It runs asynchronously; the shell does not await its completion before showing the panel or probing the engine. `--startup` suppresses that initial panel display. WPF uses explicit shutdown, so merely hiding or closing the panel does not exit.

Engine extraction/hello runs through [EngineInitialization](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.Core/EngineInitialization.cs). Overlapping retry callers share its current task. Probe failure sets Failed and retains the shell; it does not escape as an ordinary fatal startup error. Retry is enabled while Failed and the view model is not closing. Playback admission requires both engine readiness and, when muting is enabled, resolved mute recovery. Therefore shell visibility, view-model startup completion and engine readiness are separate observations.

## Data, embedded resources and process boundaries

[AppPaths](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/AppPaths.cs) normally places config and daily WPF logs under roaming `%APPDATA%/AirFlash`. Logging serializes appends and absorbs access/I/O failures; it is best effort, with no implemented size rotation beyond daily filenames. Version text comes from assembly metadata; the informational `-rc.` marker identifies previews.

The embedded engine is read completely, hashed with SHA256, and extracted beneath `%LOCALAPPDATA%/AirFlash/engine/{hash}`. An existing target is reused only when its bytes match. A unique temporary file is moved into place and cleaned on failure. Diagnostic DataDirectory isolation does **not** redirect this extraction cache: self/compatibility checks can populate it, while fake UI factories do not need extraction. Old hash directories are not reclaimed by this method.

The desktop and Rust share no memory or C-ABI. The shell's readiness probe and playback/pairing are separate short-lived/process lifetimes, described in [Session](session.md). DNS helpers also use separate processes but a distinct bounded JSON reply protocol; they do not stream audio or initialize the shell.

[AppIconService](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/AppIconService.cs) reads a separately embedded ICO, validates directory/frame bounds and selects a frame at least as large as the requested size, otherwise the largest. Window icon handles are replaced on source initialization/DPI changes and disposed on close. This lets development hosts and packaged executables use the same embedded artwork rather than depending solely on ProcessPath.

## Single instance and activation

[SingleInstance](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/SingleInstance.cs) names a Local mutex and current-user-only asynchronous pipe from the current SID. Ordinary copies, including copies in different directories, share that identity within the Windows session. An isolated suffix exists for fixtures.

A second ordinary launch connects with a three-second timeout, writes one byte and exits before creating a second settings/catalog/controller. The owner reads that byte on a background task and queues activation on the dispatcher. If Settings exists, this path calls Activate on it; unlike the tray Settings action, it does not explicitly normalize a minimized Settings window. Otherwise it shows the panel. A blocked/missing owner pipe can make the secondary startup fail visibly; mutex existence does not prove the owner's UI is responsive. Listener I/O errors are logged and end that listener task.

## Panel, tray and placement

[ControlPanel](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/ControlPanel.xaml.cs) hides on Escape, ordinary Close and deferred deactivation when no menu is open. Tray toggles guard the 240ms interval following dismissal. Actual disposal calls ShutdownPanel, detaches subscriptions, aborts pending placement and permits Close. Hiding does not Stop an owned stream; visibility changes only discovery demand.

Placement coalesces at dispatcher Loaded priority after size/DPI/catalog changes. The panel uses the tray icon's monitor work area, falling back to the cursor monitor if shell geometry is unavailable. [PopupPlacement](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.Core/PopupPlacement.cs) positions near that work area's bottom right with a scaled 12-DIP margin, caps height at 70% and clamps width. [NativeWindowPlacement](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/NativeWindowPlacement.cs) applies pixel positions/DPI scale. Settings centers on the cursor work area and reduces its nominal 880×640 and minimum 640×440 sizes for smaller work areas. Only the donation [CoffeeWindow](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/CoffeeWindow.cs#L17) calls CenterDialog to clamp against its owner's monitor. PIN and manual-entry dialogs use WPF CenterOwner placement without that explicit work-area clamp.

[TrayService](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/TrayService.cs) owns a hidden message window, icon, registration and two-second retry timer. Embedded tray-icon loading falls back to executable resources, then a privately copied system icon. [TrayRegistration](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/TrayRegistration.cs) first tries the production GUID, then window/icon identity if no identity was selected and GUID admission failed. The chosen identity persists through Explorer recreation; it is not switched on every failed Modify.

Registration negotiates version 4 callback format, falling back to legacy decoding if SetVersion fails. TaskbarCreated re-registers the selected identity; duplicate notifications can recover via Modify rather than create another entry. Failed Modify attempts Delete and re-add. Failure logs throttle each operation/identity to 30 seconds; later recovery is logged. Display/settings/DPI notifications queue icon refresh, and a successful refresh disposes the previous icon.

The menu exposes Open panel, Settings, Stop streaming and Quit. It binds Stop to the same view-model command as the panel. Disposal closes any menu, stops retry, unsubscribes status changes, deletes the registration and releases icon/message-window handles. Failed shell calls remain failure results; registration state does not prove that Explorer visibly displayed the icon or that every monitor/taskbar configuration is qualified.

## Commands, dialogs and dispatcher authority

[Commands](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/ViewModels/Commands.cs) separates synchronous RelayCommand from AsyncCommand. AsyncCommand guards its own busy state and routes exceptions to its assigned error surface; it does not serialize every command globally. State changes explicitly refresh CanExecute. UI enablement is advisory: playback authority still checks intent/owner under controller serialization.

| Surface | Current enabling/lifetime rule |
| --- | --- |
| Receiver panel toggle | Active owned row keeps Stop available; otherwise online/complete plus engine/mute readiness. Explicit start also checks current hidden options |
| Global/tray Stop | Enabled when the displayed session snapshot is active; action invalidates intent before waiting |
| PCM panel mute | Toggles session gain state; it is separate from endpoint mute and receiver device volume |
| Settings Pair | Editable, engine/mute ready, application not closing, online/complete; uses selected row plus applied application settings |
| Apply/OK/Cancel | Applying disables editing and Close; validation/binding errors gate Apply/OK; transaction completion is awaitable |
| Monitor copy | Existing serializer to clipboard, with Settings error surface on failure; no upload |
| Recovery review | Modeless, revision/owner/generation choices; unresolved mute-enabled admission remains blocked |
| PIN/manual entry | Modal owned dialogs; underlying enabled controls are not necessarily accessible |

[SettingsWindow](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/SettingsWindow.xaml.cs) lazily constructs and retains eight page templates, collapses inactive pages and resets vertical scroll when switching. [SettingsViewModel](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/ViewModels/SettingsViewModel.cs) owns draft validation, subscriptions, command state and preview disposal. Only the visible Receivers page demands discovery; only visible Monitor requests metric presentation refresh. Non-Monitor pages bind enabled state to CanEdit. The EQ horizontal band viewer forwards wheel input to the outer page's normal WPF wheel path, preserving operating-system wheel behavior. Accessible names, wrapping and normal/minimum-window scrolling are in [Settings XAML](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/SettingsWindow.xaml) and synthetic UI assertions; they are not an audit of every assistive technology.

Settings itself is modeless and singleton in App. Its close is refused while Apply runs. Manual entry and PIN are modal; [PinDialog](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/PinDialog.cs) marshals opening to the owner dispatcher, registers cancellation to Close, and rechecks cancellation after ShowDialog. Normal Stop fixtures must avoid assuming an underlying panel/tray control is reachable through that prompt. [MuteRecoveryWindow](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Ui/MuteRecoveryWindow.cs) is modeless and operates outside lifecycle/settings locks. Its Later action closes review without resolving saved obligations; modeless lifetime does not itself release mute ownership.

Discovery, endpoint, engine and session notifications marshal view-model presentation onto the dispatcher. SessionChanged additionally discards queued snapshots whose reference no longer equals the controller's current snapshot. That display filter does not replace lifecycle ownership. Production DNS Start/Cancel, audio COM, settings persistence and controller workers have their separate off-dispatcher paths. Small synchronous shell/registry/theme/network-enumeration/resource calls still exist; the code does not guarantee a hard maximum UI latency.

## Themes, localization and external actions

[ThemeService](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/ThemeService.cs) selects an explicit or current-user system light/dark palette, replaces frozen WPF/Fluent resource brushes, and listens for preference changes when in system mode. [WindowThemeService](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/WindowThemeService.cs) tracks per-window caption attributes and unsubscribes on close; unsupported DWM attributes are logged, not fatal. The production Application's ThemeMode remains System while these resource overrides implement the selected palette; the verification helper also explicitly sets ThemeMode.

Language Apply waits for the Settings transaction at ContextIdle, refreshes localization/static choices and replaces panel/tray/Settings windows while retaining the AppViewModel/controller. It reopens previously visible Settings with its selected page; otherwise it restores a previously visible panel. If both were visible, only Settings reopens through this branch. It closes recovery review and recreates tray registration. This is not a playback restart. Chinese catalog selection/fallback and preserved dynamic keys are described in [Settings](settings.md). Regional formatting culture and catalog language are independent fixture dimensions.

[Autostart](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/Autostart.cs) writes/deletes a current-user Run entry for the current executable with `--startup`; it does not install a service. Startup reconciles the applied preference asynchronously. Apply changes it before saving and attempts rollback if persistence fails; rollback failure is reported explicitly.

[UpdateService](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.Core/UpdateService.cs) queries original Ding-Kyoma releases/latest, not ThatMarko releases. It has linked 15-second cancellation; callers cap response buffering at 1 MiB. 404/draft/prerelease means no stable candidate. A strictly parsed version constructs the destination from the trusted repository and validated tag, ignoring API-supplied HTML destinations. Settings shows status, and only its Download action opens that page through the shell; nothing downloads, installs or restarts automatically. Closing Settings cancels its UpdateCheckState and invalidates late results. Open logs, download, licenses and donation windows are user-invoked shell/UI actions, not background upload paths.

## Shutdown and failure boundaries

[App.Quit](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/App.xaml.cs#L175) sets its shell-only `_quitting` flag, waits for any Settings Apply, closes Settings/recovery, then awaits engine-probe disposal **before** view-model disposal. [AppViewModel.DisposeCoreAsync](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/ViewModels/AppViewModel.cs#L613) then sets `_closing`, invalidates automatic intent, stops timers and disposes discovery before its first await.

**At this page's historical `0623787` source, the initial Quit request was not an immediate admission barrier.** During the earlier Settings/probe awaits the view model's closing flag/timers had not yet been changed. A queued automatic admission or explicit command was source-permitted until that disposal entry. The dated correction above now reproduces and fixes that interval; this paragraph preserves the original source trace.

View-model disposal awaits startup, drains endpoint enumeration/notifications and settings serialization, attempts the final dirty save, then disposes session and audio. Session cancellation/cleanup restores exact owned mute best effort. Only afterward does the normal Quit path dispose tray/panel, activation pipe/mutex and theme, then explicitly shuts down WPF. Its outer catch logs a disposal exception and the finally still calls Shutdown; an exception from an earlier step can skip later sequential disposals. These paths are not a bounded cleanup guarantee or physical crash/power-loss qualification.

Unhandled dispatcher exceptions are marked handled and become a notice once a view model exists. Before it exists, startup failures produce diagnostic JSON or a message box/log location and exit 1. Ordinary OnStartup failure invokes Quit; engine probe failure instead stays in the usable retry shell. Error presentation can overwrite the last notice; daily logs and controller fault snapshots have different retention rules.
