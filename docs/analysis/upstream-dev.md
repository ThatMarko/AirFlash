# Excluded upstream development snapshot

The runtime baseline for these notes is `41190e0d13a63a714c08dffe73ababca1804875c`. Documentation commit `c077a0577de26ad7e44b8fd50f62456e12965fb0` is the audited fork baseline; it changes no runtime source. The separate development commit `67435a4e0df6a40e5e709e2b75dc9b24a457dda6` is one commit after `41190e0`, **not** after `c077a05`, and is not merged into this checkout. These are local commit identities, not claims that remote branch tips still point there.

This page checks the previously documented differences using the pinned development commit and `git diff 41190e0 67435a4`. It does not import them into the main workflow or qualify that development build for hardware use. The earlier claim that a particular version was already published as a draft prerelease is not established by source: publication state is external, and a draft is not a published release. The pinned [release workflow](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/.github/workflows/release.yml) preserves preview artifacts for maintainer publication. Baseline [`UpdateService.cs:10–27`](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/UpdateService.cs#L10-L27) queries the stable latest endpoint and explicitly ignores draft/prerelease responses; it does not subscribe to `dev`.

## What the pinned comparison establishes

| Area | Difference in `67435a4`, excluded from the baseline |
| --- | --- |
| Discovery | `WindowsDiscovery.cs` is unchanged: browse, resolve, ninety-second record expiry, pending-token handling, and adapter filtering retain the baseline behavior. There is no new discovery-loss grace period |
| Identity | `ReceiverIdentity.cs` is unchanged. `ReceiverCatalog` additionally merges per-receiver transport/timing options, but retains the canonical-id walk |
| Desktop command | [SessionController](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/desktop/AirFlash.Core/SessionController.cs) sends advertised services, `timing` and `transport` defaulting to `auto`, and `compatibility_buffer_ms`. Per-receiver overrides can replace those defaults |
| Latency | [Settings](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/desktop/AirFlash.Core/Settings.cs) retains 120/200/500 ms presets and extends per-receiver custom validation and effective custom clamping to 10,000 ms; global custom validation remains 0–2000 ms. A non-null receiver `LatencyMode` or global custom/realtime mode supplies the compatibility override; a receiver `CustomBufferMs` value alone does not trigger it. Native [session inspection](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/session.rs) defaults a single non-HomePod in non-legacy mode to 3000 ms; HomePod/legacy/stereo paths use requested latency |
| Restart signature | [Receiver.TransportKey](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/desktop/AirFlash.Core/Receiver.cs) includes advertised negotiation fields, and the session signature also includes transport, timing, and compatibility buffer. Changes can restart active playback; this is absent from the baseline signature |
| Endpoint selection | Native `PreparedPeer::inspect` tries the primary endpoint and distinct advertised service endpoints, prioritizing AirPlay service alternatives after nonterminal errors. Any classified `Fault` or rejection 401/403/470 stops inspection instead of trying the next endpoint. DNS-SD itself still provides IPv4-only records through the unchanged discovery implementation |
| Negotiation | [Capabilities/Profile](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/capabilities.rs) chooses realtime UDP type 96 or buffered TCP type 103, PTP/NTP, PCM/ALAC, and 44.1/48 kHz subject to capabilities and overrides. HomePod models start with `AudioAccessory` or `HomePod`; automatic timing prefers PTP for them and for stereo/legacy paths. This is not a guarantee that every receiver supports every combination |
| Recovery | Native session code has conditional clock/format/transport fallbacks. Clock/transport fallback branches require their respective requested automatic modes plus advertised support, rejection status, and SETUP stage. Format fallback instead requires non-legacy 48 kHz, advertised 44.1 kHz support, audio SETUP, and status 415; it does not require automatic timing/transport. None is unconditional fallback on every failure |
| Unsupported controls | [Feedback](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/transport.rs) and [volume](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/volume.rs) recognize 404/405/501 as unsupported for their respective requests. Rejected volume writes still settle as unconfirmed; unsupported controls do not imply working audio |
| Pairing | Status 470 is classified `pairing_required`, nonretryable. [Authentication](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/auth.rs) maps transient TLV rejection code 2 to the same guidance. Other transient authentication failures are not all reclassified as pairing-required |
| Equalizer | Native [equalizer control](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/native/airflash-engine/src/equalizer.rs) stores settings/rate and rebuilds at the negotiated sample rate, retaining edits received during negotiation. Ten bands and Q 1.4 remain |
| Diagnostics | The desktop consumes `negotiated` events and displays effective format, clock, transport, buffer, and fallback reasons. Those results remain distinct from measured acoustic latency |

The pinned [compatibility notes](https://github.com/Ding-Kyoma/AirFlash/blob/67435a4e0df6a40e5e709e2b75dc9b24a457dda6/docs/AIRPLAY-COMPATIBILITY.md) explicitly call third-party support experimental, contain no new third-party hardware qualification results, and require HomePod stereo regression. Reading those notes does not establish a successful hardware test. Moving runtime source to this commit would require auditing the session, handshake, settings, timing, and restart documentation again. It would leave the discovery implementation unchanged, while changing downstream behavior.
