# Credentials and the process boundary

The WPF app and `airflash-engine.exe` have no shared-memory integration or C-ABI. Their process interface is JSONL over redirected stdin/stdout. The desktop passes pairing commands/PINs and receives status; the Rust engine both writes and reads its own DPAPI files. Those files are not a second desktop IPC channel: WPF does not deserialize private keys. See [Session](session.md) for lifecycle and [Engine](engine.md) for the handshake.

## Process and pipes

[`AppPaths.ExtractEngine`](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.App/Services/AppPaths.cs#L30) reads embedded resource `AirFlash.Engine.exe`, hashes its bytes with SHA-256, and uses `%LOCALAPPDATA%\AirFlash\engine\<hash>\airflash-engine.exe`. An existing target is reused only if its actual contents hash to that expected value; a missing or mismatching target is replaced. The write uses a UUID `.tmp` file in that directory, `File.Move` with overwrite, and a `finally` cleanup of the temp path ([AppPaths.cs:22–42](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.App/Services/AppPaths.cs#L22)).

[`ProcessEngineConnection`](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/EngineConnection.cs#L26) starts the executable with stdin, stdout, and stderr redirected and no window. Stdin explicitly uses UTF-8 without BOM; stdout/stderr are decoded as UTF-8, and native events are UTF-8 JSON plus newline. Each command is one JSON line. A writer semaphore prevents interleaving pipe writes. Native `send` locks stdout across writing/flushing a complete event so worker and command-thread events cannot interleave. `ReadAsync` takes the next stdout line ([EngineConnection.cs:26–51](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/EngineConnection.cs#L26), [main.rs:22–34](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L22)).

[`main.rs:54–110`](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L54) bounds native command input at 65,536 bytes including LF (and CR for desktop CRLF). Oversized lines are drained through newline without accumulating the whole line, then emit `error` with `IPC command exceeds 64KiB`; a final unterminated JSON line is also parsed on EOF. Native event output is not size-capped. The desktop limits a completed stdout line to 65,536 UTF-16 characters after `ReadLineAsync` has allocated it; it imposes no outgoing-command size limit ([EngineConnection.cs:34–51](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/EngineConnection.cs#L34)). The repository does not enforce a universal 64 KiB-per-line limit in both directions.

`send` stamps any `error` lacking a `code` with `command_error`, null host, channel `ipc`, and retryable false. Envelope schema rejection (`deny_unknown_fields`), malformed JSON, unsupported version, unknown command, and invalid start/probe parameters follow this path. `Peer`, `ProbeOptions`, equalizer settings, and equalizer-update objects also reject unknown fields; arbitrary `params` for commands such as `set_gain`, `stop`, or `pair_pin` are not uniformly schema-checked ([main.rs:12–34,117–140,174–237](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L12)). There is no `ipc_error` or `line_too_long` code.

Events include `version`, `id`, and `session_id`. Malformed/oversized input errors use empty ids. Worker events echo the initiating start/pair request id; update replies echo their own request id. `ReadEventAsync` accepts only version 1 and the attempt's session id, without correlating `id`; nonmatching lines are skipped inside the same read budget. JSON parse/type failures can still fail the desktop read rather than being silently discarded ([SessionController.cs:441–454](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/SessionController.cs#L441)).

Stdout is reserved for events. The desktop appends every received stderr line to its log without a redaction filter. The native command loop does not normally print commands/PINs/keys to stderr; avoiding secrets in diagnostics is a coding requirement, not an enforced sanitizer ([EngineConnection.cs:30–33](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.Core/EngineConnection.cs#L30)).

Desktop shutdown closes stdin, waits two seconds, and calls `Process.Kill(true)` if the process still runs, then awaits exit/stderr drainage. EOF drops `Running`, sets cancellation, and joins its worker. A matching `stop` also cancels and joins the worker before its reply; even a nonmatching `stop` replies `stopped` without cancelling the current worker. Neither `stop`, `hello`, nor worker completion exits the native command loop. A new valid `start`, `probe`, or parsed `pair` drops the previous worker before spawning its replacement; rejected replacement parameters leave the existing worker intact. The desktop uses a new process per playback attempt ([main.rs:36–52,117–163,238–259,324–340](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L36)).

The desktop uses `hello` in a separate process during normal startup, before discovery `Start`, and also in self-check. The check has a ten-second timeout, requires event `hello` and version 1, and reads `engine_version`; it does not filter the response's ids. The engine also reports `mode: native`, `qualification: partial`, `live_loopback: true`, `production_ready: false`, and commands `hello`, `start`, `probe`, `stop`, `set_gain`, `set_equalizer`, `set_device_volume`, `pair`, `pair_pin`. The check process is disposed before any receiver is contacted; hello itself merely replies. `production_ready: false` is the engine's label and does not select desktop behavior ([App.xaml.cs:55–65,125–138](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/desktop/AirFlash.App/App.xaml.cs#L55), [main.rs:111–115](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L111)).

## What a pairing file contains

[`credentials.rs`](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/credentials.rs) stores one file per accessory id:

```text
%APPDATA%\AirFlash\native-credentials\<sha256>.dpapi
```

The hash input is the id with `:` removed and ASCII letters lowercased; other separators/whitespace are retained. `directory()` uses `APPDATA`, falling back to relative `AirFlash/native-credentials` if the variable is missing. The file starts with five bytes `W2AP\x01`, followed by user-scoped `CryptProtectData` output with entropy `AirFlash HAP credentials v1` and UI forbidden. No machine-scope flag is set ([credentials.rs:18–64](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/credentials.rs#L18)).

`load` first returns `None` when `path.exists()` is false. Rust's existence probe also returns false for metadata/access errors, so an inaccessible path may look absent and permit transient setup ([Rust `Path::exists`](https://doc.rust-lang.org/std/path/struct.Path.html#method.exists)). After a true existence check it validates metadata size at most 16,384 bytes before reading, magic, DPAPI decrypt, JSON deserialization, and nonempty identities; those errors abort rather than falling back. The JSON stores identities as byte arrays (`Vec<u8>`), not strings, with fixed 32-byte controller-secret/accessory-public arrays. Unknown JSON fields are not explicitly denied by `Credentials`. The metadata size check is not a race-proof bounded reader ([credentials.rs:105–121](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/credentials.rs#L105), [auth.rs:152–158](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/auth.rs#L152)).

`save` creates `<uuid>.tmp` in that directory with `create_new`, writes the magic/encrypted payload, calls `sync_all`, closes the file, then uses `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`. There is no leading dot or separate `flush` call. Failure attempts to delete the temp file. The destination is replaced by the move rather than truncated in place. A crash before the move may leave the previous file and a temp file; crash/power-loss durability is not tested here. Legacy pyatv files are not read or modified. Serialized cleartext and DPAPI buffers use `Zeroizing`; `Credentials` zeroizes on drop ([credentials.rs:76–103](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/credentials.rs#L76), [auth.rs:152](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/auth.rs#L152)).

The filename input is `/info` `deviceID` during `pair`, distinct from the authenticated HAP accessory identity inside the saved payload. They are not compared at save time. Desktop catalog ids/aliases are not inputs. A change that alters the normalized `/info` filename hash does not find the old file; case or colon-only changes preserve that hash ([main.rs:265–297](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L265)).

`pair` writes the file without enabling the playback cipher. The following `start` loads and verifies credentials. If `load` returns `None`, or playback `/info` has no nonempty string identity, it uses transient setup with PIN `3939` without writing a file. Credential-load errors after a true existence check fail playback rather than selecting transient ([session.rs:231–251](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/session.rs#L231)). See [Engine](engine.md).

## Command handling

| Command | Effect |
| --- | --- |
| `hello` | Replies with the self-description. No sockets opened by this command; the loop remains alive |
| `set_gain` | Matching `Running`: validates/stores gain and replies `gain_changed`, or returns stamped `command_error`. No matching session: silently ignored. A pairing worker permits only gain 0 |
| `set_equalizer` | Requires a matching stored `start` entry/control slot and positive sequence, including during setup or after its worker has finished. Prepares coefficients and replies `equalizer_changed`, or returns nonfatal `equalizer_error`; this acknowledges preparation, not receipt by the DSP |
| `set_device_volume` | Matching non-pairing worker: queues volume 0–100 with positive sequence, or returns `device_volume_error`. Other targets are ignored. Socket requests happen later on the volume worker |
| `stop` | Cancels/joins only the matching worker, but replies `stopped` in every case. Does not exit the process |
| `pair` | Starts one persistent-pairing TCP connection; the loop remains alive after success/failure. Unlike `start`/`probe`, this command does not reject IPv6 or port zero after parsing `Peer` |
| `pair_pin` | Sends a string to a matching pairing worker's channel; other targets are ignored |
| `start` | The playback handshake in [Engine](engine.md) |
| `probe` | Finite qualification: duration 1–5000 ms, gain 0–0.1, disabled equalizer, one/two distinct IPv4 peers, and rate 44100/48000 ([session.rs:89–127](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/session.rs#L89)) |

The table follows [main.rs:174–329](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/main.rs#L174). `Running` can remain present after its worker finished, so matching a stored session id does not prove healthy playback. These commands do not open a process; the desktop creates it and sends commands through stdin.

## Source verification and coverage

Audited against runtime source upstream `41190e0` in documentation baseline `c077a05`. Test implementations below were inspected; that is not a record of executing the .NET/Rust suites in this audit. [credentials.rs:127–134](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/src/credentials.rs#L127), `dpapi_roundtrip_and_tamper`, verifies protect/unprotect and tamper rejection, not `save`/`load`, atomic replacement, filename normalization, or crash recovery. [equalizer_ipc.rs:9](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/tests/equalizer_ipc.rs#L9) uses a real child process with invalid commands and checks that nonfatal equalizer/probe errors leave hello responsive. [rtsp_contract.rs](https://github.com/Ding-Kyoma/AirFlash/blob/41190e0d13a63a714c08dffe73ababca1804875c/native/airflash-engine/tests/rtsp_contract.rs) covers the network parser, not JSONL envelope/line limits.

No dedicated existing test was found for the native 65,536-byte boundary, desktop line allocation, unmatched stop/gain handling, or process-tree kill. No credential files, PINs, or real-device connections were read or created for this audit.
