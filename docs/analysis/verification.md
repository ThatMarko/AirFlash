## Diagnostic modes are not interchangeable

[Program](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Program.cs#L9-L42) selects startup data/log isolation for the exact supported switches before WPF/platform initialization. Unknown `*-check` switches and values ending in `-check` do not change ordinary startup data. The broader fatal-error dialog predicate is separate. DNS helper modes dispatch even earlier, before normal application paths and WPF are initialized.

| Mode | Actual work and boundary |
| --- | --- |
| `--ui-smoke`, `--tray-smoke` | Actual WPF/Windows shell with injected services; narrow submodes select pairing, settings recovery, mute, scrolling, readiness or Monitor checks. Tray/clipboard fixtures can use the real shell/clipboard, without a real receiver |
| `--stability-check` | Simulated application lifecycle/discovery, with its own temporary data directory |
| `--ui-perf` | Actual WPF with injected enumeration/save/Stop delays; measures dispatcher/page/Apply/EQ timings. Reported `targets` can be false while `ok` is true; callers must inspect the target fields to enforce those budgets |
| `--self-check` | Extracts the embedded engine and runs bounded hello; no pairing/playback |
| `--compat-check` | Windows capability/DNS-SD entry-point checks and native hello; its own report explicitly leaves Windows 10 execution pending and does not exercise discovery/pairing/playback |
| `--audio-check` | Real, read-only MTA endpoint enumeration/default identity; no playback or mute changes |
| `--discovery-check` | Real Windows DNS-SD for eight seconds; this is a network operation, not a fake discovery test |
| `--update-check` | Production updater network/JSON/version path; not a release or installation |
| `--discovery-perf` | Real Windows DNS-SD performance check: 150 seconds visible, twenty-five 400-ms Start/Stop cycles and 120 seconds hidden, plus overhead; reports logical queries, retained owners and process resource samples. No audio or saved settings |
| `--dns-resolve-helper-check` | Synthetic actual helper-process admission/cancellation/exit; separate early dispatch, not production receiver resolution |

Implementation and serialization are in [App diagnostics](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/App.xaml.cs#L78-L99), [standalone checks](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/App.xaml.cs#L207-L261), [discovery performance](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Verification/DiscoveryPerf.cs) and [UI performance](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Verification/UiPerf.cs#L113-L125). Isolation is mode-specific and some harnesses reassign their data directory after startup. It is not a blanket guarantee of no machine interaction: [engine extraction](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/desktop/AirFlash.App/Services/AppPaths.cs#L30-L42) always uses the normal `%LOCALAPPDATA%/AirFlash/engine/<SHA>` cache, independently of `DataDirectory`. Self/compat checks can populate that cache even with isolated logs. The fake UI path does not extract the engine. Neither real discovery mode ran in this documentation task.

Diagnostics write output only when the relevant output argument is provided; consumers must require fresh report existence, successful exit and applicable result fields. `ok` has each mode's stated scope. It does not certify every application invariant.

## Remaining source and measurement limits

Source review distinguishes the command process, worker, event reader, local capture counters and physical receiver. A readable pipe/process hello or inactive read timeout is not proof of healthy capture/audio output. Successful UDP sends and local padding counters do not measure loss, playout, PTP lock or acoustic latency. Native localhost tests deliberately bound protocol pieces, rather than claiming a whole emulated AirPlay receiver.

The historically mapped `0623787` source also left bounded behaviors that tests did not universalize: a PIN-open Pair reader queues terminal events until prompt handling resumes; browse settlement counts protected managed sections without proving the reverse P/Invoke native return stack has unwound; and mute restoration/recovery remains best effort and physically unqualified. Those limits remain distinct from the shell Quit admission gap, now repaired by the dated supplement above. The corresponding [failures](failures.md), [desktop shell](desktop-shell.md), [discovery](discovery.md) and [mute](control-and-mute.md) maps explain them.

[Finite probe tooling](https://github.com/ThatMarko/AirFlash/blob/06237873dcb6394eb35e97a017c536843bd7743d/scripts/native_probe.py) enforces duration at most five seconds and gain at most 0.1. A fixture of its validation/reporting is not authorization or evidence of a real-device execution. Hardware reliability, firmware tolerance, local credential store, physical power-loss durability and actual Windows 10 remain separate qualification work. This all-page task runs source/document checks only; no runtime behavior is changed.
